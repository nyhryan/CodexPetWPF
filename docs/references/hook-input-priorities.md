# Codex 훅 입력 정보의 필요도

## 기준

이 문서는 현재 [프로젝트 훅 설정](../../.codex/hooks.json)에 등록된 각 훅의 표준 입력 JSON을 CodexPet 위젯에 얼마나 필요한지에 따라 정리한다. 필드 설명은 저장소의 [Codex 훅 참고 문서](codex-hooks.md)를 기준으로 했다. 실제 입력 필드와 이벤트 발생 순서는 Codex 버전과 실행 상황에 따라 확인이 필요하다.

필요도는 **현재 상태 이미지와 캡션을 표시하는 기능**을 기준으로 판단한다. 아래의 도구 이름 표시 아이디어는 아직 구현이나 확정된 요구사항이 아니다.

1. **현재 필수**: 지금의 상태 전환에 사용한다.
2. **아이디어에 필요**: 이미지 위 문구에 도구 이름을 표시한다면 사용한다.
3. **조건부**: 진단이나 향후 기능을 선택할 때만 필요하다.
4. **현재 불필요**: 현재 표시와 도구 이름 표시에는 필요하지 않다.

이 구분은 Codex가 훅의 표준 입력에 어떤 필드를 넣는지를 바꾸는 설정이 아니다. 훅이 입력을 읽은 다음 **위젯으로 무엇을 전달할지** 판단하기 위한 것이다. 현재 구현은 원본 JSON 전체를 파이프로 전달하며, 아래는 변경 제안이지 이미 적용된 동작이 아니다.

## 공통 필드의 우선순위

| 순위 | 필드 | 판단 |
|---|---|---|
| 1 | `hook_event_name` | **현재 필수.** 이벤트를 구분해 이미지를 선택한다. 단, 아래에서 설명하는 상태에 영향을 주지 않는 이벤트는 이벤트 전체를 전달하지 않아도 현재 화면은 같다. |
| 3 | `session_id` | **조건부.** 현재 화면은 세션을 구분하지 않지만 훅과 위젯의 진단 로그에는 기록한다. 세션별 표시나 집계를 추가하면 필요할 수 있다. 제거할 경우 현재 로그와 테스트의 사용도 함께 검토한다. |
| 3 | `cwd`, `model` | **조건부.** 현재 화면에는 사용하지 않는다. 프로젝트나 모델을 표시하는 기능을 결정할 때만 검토한다. `cwd`에는 로컬 경로가 들어간다. |
| 4 | `transcript_path` | **현재 불필요.** 대화 기록 파일의 경로이며 이미지나 도구 이름을 표시하는 데 필요하지 않다. |
| 4 | `permission_mode` | **현재 불필요.** 일부 훅에 포함되는 권한 모드다. 현재 승인 대기 이미지는 이벤트 이름으로만 선택한다. |

여기에 없는 필드도 자동으로 전달하기보다, 실제 기능에 필요한지 확인한 뒤 선택하는 편이 좋다.

## 훅별 필드

아래 표의 공통 필드는 위 표를 따른다. 각 행은 해당 훅에서 추가로 고려할 정보를 필요도 순서로 표시한다. `없음`은 **현재 이미지 표시 기준**이며, 진단 로그용 공통 필드까지 지금 당장 삭제해도 된다는 뜻은 아니다.

| 훅 | 현재 필수 | 아이디어에 필요 | 조건부 또는 현재 불필요 |
|---|---|---|---|
| `SessionStart` | `hook_event_name`, `source` | 없음 | `source`가 `compact`이면 상태를 유지한다. 그 외 공통 필드는 위 기준을 따른다. |
| `SessionEnd` | `hook_event_name` | 없음 | `reason`은 현재 불필요하다. |
| `UserPromptSubmit` | `hook_event_name` | 없음 | `turn_id`는 세션·턴 구분 기능을 추가할 때만 검토한다. `prompt`는 현재 불필요하며 사용자 요청 본문이므로 전달하지 않는 편이 좋다. |
| `PreModelRequest` | `hook_event_name` | 없음 | `model`, `turn_id`, 사용 가능한 경우 `agent_id`, `agent_type`은 세부 표시나 집계 기능을 추가할 때만 검토한다. |
| `PostModelRequest` | `hook_event_name` | 없음 | 위 모델 요청 식별 정보와 `status`, `error`, `token_usage`는 현재 불필요하다. 오류 내용은 민감한 정보를 포함할 수 있다. |
| `PreToolUse` | `hook_event_name` | `tool_name` | `turn_id`, `tool_use_id`는 호출별 추적에만 필요하다. `tool_input`은 현재 불필요하며 명령과 도구 인자 등 민감한 내용이 들어갈 수 있다. |
| `PermissionRequest` | `hook_event_name` | `tool_name`: 승인 대기 중인 도구 이름도 표시하기로 한다면 필요 | `turn_id`는 호출 추적에만 필요하다. `tool_input`과 그 안의 `description`은 현재 불필요하며 명령, 인자 또는 승인 사유를 포함할 수 있다. |
| `PostToolUse` | `hook_event_name` | `tool_name`: 도구 실행 후에도 이름을 표시하기로 한다면 필요 | `turn_id`, `tool_use_id`는 호출별 추적에만 필요하다. `tool_input`과 `tool_response`는 현재 불필요하며 명령, 인자, 결과 등 민감한 내용이 들어갈 수 있다. |
| `Stop` | `hook_event_name` | 없음 | `turn_id`는 턴 구분에만 필요하다. `stop_hook_active`, `last_assistant_message`는 현재 불필요하다. 마지막 응답에는 대화 내용이 포함될 수 있다. |
| `Interrupt` | `hook_event_name` | 없음 | `turn_id`는 턴 구분에만 필요하다. |
| `PreCompact` | 없음 | 없음 | 현재 상태에 영향을 주지 않는다. `turn_id`, `trigger`를 포함한 이벤트 전체가 현재 화면에는 불필요하다. |
| `PostCompact` | 없음 | 없음 | 현재 상태에 영향을 주지 않는다. `turn_id`, `trigger`를 포함한 이벤트 전체가 현재 화면에는 불필요하다. |
| `SubagentStart` | 없음 | 없음 | 현재 상태에 영향을 주지 않는다. `turn_id`, `agent_id`, `agent_type` 등을 포함한 이벤트 전체가 현재 화면에는 불필요하다. |
| `SubagentStop` | 없음 | 없음 | 현재 상태에 영향을 주지 않는다. `turn_id`, `agent_id`, `agent_type`, `agent_transcript_path`, `stop_hook_active`, `last_assistant_message` 등을 포함한 이벤트 전체가 현재 화면에는 불필요하다. 마지막 응답은 민감한 내용을 포함할 수 있다. |

현재 코드에는 위 네 가지 상태 미변경 이벤트도 파이프로 전달하고 진단 로그에 기록하는 동작이 있다. 전달 자체를 생략하면 화면은 같지만 이 진단 기록은 달라진다.

## 도구 이름 표시 아이디어

사용자 아이디어: **도구를 사용할 때 이미지 위 문구에 어떤 도구를 사용하는지 표시한다.** 이름만 표시한다면 `tool_name`이 출발점이며 도구 입력과 결과는 필요하지 않다. 훅 문서의 예시는 `Bash`, `apply_patch`, `mcp__fs__read`다. 훅에 보고되는 이름은 실제 호출 경로에 따라 사용자가 보는 이름과 다를 수 있다.

구현 전에는 다음을 정해야 한다.

- `PreToolUse`에서만 표시할지, `PostToolUse`와 `PermissionRequest`에서도 표시할지와 도구 종료 후 이름을 언제 지울지.
- 도구 이름이 없거나 길 때의 표시 방식과 기존 사용자 지정 캡션과의 관계.
- 현재는 같은 상태의 이벤트가 연속해서 오면 화면을 갱신하지 않는다. 작업 중 이미지가 유지되는 동안 다른 도구가 시작되어도 이름은 갱신해야 할 수 있다.
- 여러 세션의 이벤트는 도착 순서대로 반영된다. 동시 도구 호출이나 세션이 겹칠 때 어떤 이름을 보여줄지와 호출별 추적에 `session_id`, `turn_id`, `tool_use_id`가 필요한지.

이 기능을 선택하기 전까지 `tool_name`을 전송해야 한다는 뜻은 아니다.

## 전송 최소화의 출발점

현재 이미지 기능만 유지한다면 상태 전환 이벤트에는 `hook_event_name`을 보내고, `SessionStart`에는 `source`를 추가하면 된다. 진단 로그의 `session_id`와 위의 상태 미변경 이벤트 기록은 별도 결정이 필요하다. 도구 이름 표시를 추가하기로 한다면 선택한 도구 이벤트의 `tool_name`을 더한다.

최소화는 파이프에 전달되는 정보의 양을 줄이지만 파이프 상대방의 신원을 검증하지는 않는다. 또한 훅의 표준 입력에 원본 정보가 들어오는 것 자체를 막지는 않는다.
