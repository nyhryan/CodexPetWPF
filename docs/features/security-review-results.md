# Spec 3 보안 점검 결과

## 점검 범위와 환경

2026-11-09, Windows x64 빌드 26200, .NET SDK 10.0.403 및 로컬 .NET 런타임 10.0.14에서 커밋 `a4d72f4`와 Spec 3 작업 트리 변경분을 Debug 구성으로 검사했다. 설치 파일이나 게시된 self-contained 런타임은 검사하지 않았다. 자동 검사는 `dotnet build CodexPet.slnx --no-restore -m:1 -p:UseSharedCompilation=false`와 `dotnet run --project CodexPet.Tests --no-build -- --integration`으로 실행했다. 검사 데이터는 합성 데이터이며 설정·이미지는 임시 폴더를 사용했다. 통합 검사는 실제 이름의 파이프와 새 진단 로그를 사용한다.

## 구현 및 검증 결과

- 훅 입력은 최대 1 MiB, 읽기 시간은 1초다. 크기 초과 또는 시간 초과 시 이벤트를 버리고 종료 코드 0을 반환한다. 일반적인 이벤트의 실제 크기 분포는 아직 측정하지 않았으므로 1 MiB를 초과하는 정상 이벤트는 표시되지 않을 수 있다. 앱 수신은 연결당 최대 4 KiB의 개행 종료 메시지와 2초 읽기 제한을 적용한다. 초과, 개행 없는 입력, 무응답, 잘못된 JSON 이후 정상 이벤트 수신을 검사했다. 연속적으로 연결을 점유하면 이벤트 유실과 지연이 계속될 수 있다.
- 훅은 화면에 쓰는 알려진 이벤트만 전달한다. `SessionStart`의 source는 `startup`, `resume`, `clear`, `compact`, `fork`만 전달한다. source가 없거나 타입·값이 잘못되면 source 없이 전달하고 대기 상태로 전환한다. `compact`는 현재 상태를 유지한다. 잘못된 JSON, 빈 입력, 필수 이벤트명 누락은 이벤트를 버린다. 알 수 없는 이벤트와 네 가지 미사용 이벤트는 전달하지 않는다. 테스트는 중첩 입력을 포함한 합성 민감 표식과 세션 ID가 실제 파이프 메시지 및 새 로그에 없는지, 상태 전환과 같은 상태의 GIF 유지, 미실행 위젯 및 입력 정지 시 훅의 정상 종료를 확인했다.
- 별도 테스트 파이프 서버가 먼저 같은 이름을 사용하면 훅이 그 서버에 축소된 이벤트를 전송했다. 실제 앱 서버에도 같은 사용자 테스트 프로세스가 훅을 거치지 않고 이벤트를 전송할 수 있었다. 상대 실행 파일 인증이 없기 때문에 같은 계정의 다른 프로세스는 상태를 위조하거나 서버를 선점할 수 있다. 선점 시 축소된 이벤트명과 source가 노출되고 앱 서버가 시작하지 못할 수 있다. 이는 **미해결**, 영향은 로컬 상태 표시와 이벤트 메타데이터에 대한 것이며 계정 침해나 권한 상승을 재현한 결과는 아니다. 0.1.0에서 이 제한을 수용할지와 추가 인증 필요성은 릴리스 담당자가 결정해야 한다. `CurrentUserOnly`의 다른 사용자 차단과 관리자 권한·다른 무결성 수준에서의 동작은 별도 계정 환경에서 아직 검증하지 않았다.
- 진단 메시지는 실패 유형만 기록하고 예외 메시지나 이벤트 원문은 기록하지 않는다. 새 로그의 크기·파일 수 제한, 오래된 파일 교체, 기존 로그 보존 및 기록 실패 시 계속 진행을 임시 폴더에서 검사했다. 설정·이미지의 격리된 저장, 누락·손상 복구도 기존 자동 검사로 확인했다. 파일 ACL, 권한 변경, 실행 파일이나 설정 변조의 실제 영향은 아직 검사하지 않았다.
- 2026-11-09 `dotnet list CodexPet.slnx package --vulnerable --include-transitive --no-restore`를 NuGet 소스 `https://api.nuget.org/v3/index.json`으로 실행했을 때 알려진 취약 패키지는 보고되지 않았다. 직접 의존성은 앱의 `XamlAnimatedGif` 2.3.2이며 테스트 프로젝트는 이를 추이적으로 참조한다. 훅에는 NuGet 패키지 참조가 없다. 이는 해당 시점에 조회 가능한 데이터의 결과이며 OS, .NET 런타임, 최종 설치 도구·배포물 전체에 대한 취약점 검사는 아니다. 게시 런타임 및 Inno Setup의 실제 버전·출처와 라이선스 검토는 배포물 준비 후 다시 확인한다.

## 사용자 로그 안내

새 로그는 `%LOCALAPPDATA%\CodexPet\Logs\v2`에 컴포넌트별 `app.log`, `hook.log`와 각각의 `.1`, `.2`로 저장한다. 각 파일은 최대 256 KiB, 컴포넌트별 최대 3개이며 회전할 때 가장 오래된 파일부터 교체한다. 오류가 없으면 파일이 없을 수 있다. 로그를 쓸 수 없어도 앱과 훅은 계속 동작한다.

이전 버전의 `%LOCALAPPDATA%\CodexPet\Logs\app.log` 및 `hook.log`는 자동으로 삭제하거나 회전하지 않는다. 이전 로그에는 세션 ID 등이 남아 있을 수 있다. 사용자가 파일 탐색기 주소창에 `%LOCALAPPDATA%\CodexPet\Logs`를 입력해 열고 원하는 이전 로그 파일을 직접 삭제할 수 있다. 설정과 이미지에는 이 로그 정리 정책이 적용되지 않는다.

## 릴리스 전 미완료 항목

- 다른 사용자 및 권한 수준별 파이프 접근, 같은 사용자 위조·선점의 대응 또는 수용 판단, 연속 점유의 실사용 영향과 정상 Codex 입력 크기를 확인한다. 릴리스 담당자는 아직 지정되지 않았다.
- Spec 2의 설치·전역 훅 등록·삭제 구현이 없으므로 기존 훅 병합, 경로 인용, 재설치·업데이트·제거, 권한 오류와 사용자 데이터 보존은 검증하지 못했다. 격리된 Windows 환경에서 구현 후 검사한다.
- 실제 설치 파일과 공식 다운로드 위치가 아직 없다. 0.1.0은 서명 없이 준비하고, 게시 안내에 Windows의 게시자 미확인 또는 SmartScreen 경고 가능성과 공식 GitHub Releases 위치를 명시한다. 설치 파일을 준비한 뒤 `Get-FileHash -Algorithm SHA256 -LiteralPath <설치파일>`의 결과를 신뢰할 수 있는 경로로 제공된 해시와 비교한다. 해시 일치는 파일 비교이며 게시자 신원 증명은 아니다.
- 설치 파일의 실제 서명·해시, 포함 런타임과 설치 도구 및 알려진 취약점, 라이선스 고지를 검사한다. 실제 배포물에서 재현 가능한 데이터 노출·설치 손상이나 정상 사용을 막는 문제는 릴리스 차단 후 수정·재검증한다. 그 외 제한도 영향과 근거를 기록하고 지정될 릴리스 담당자가 Spec 4에서 수용 여부를 결정한다. 현재 이 문서는 릴리스 승인이나 보안 점검 완료를 뜻하지 않는다.

## Spec 2 구현 후 추가 확인

2026-11-10 설치·훅 관리 구현이 추가되었다. 기본 설정과 다른 파일을 사용하는 격리 시험에서 기존 훅 보존, 등록 중복 방지, 훅 변경 시 제거 중단, 잠긴 설정의 등록 실패와 복구 후 재시도를 확인했다. 설치 위치 변경 시도와 위젯 실행 중 설치·제거도 중단했다. 시험용 빌드에서 데이터 삭제 선택을 모의해 대상 파일 삭제와 다른 파일 보존을 검사했다. 시험용 Inno 설치본은 실제 사용자 Codex 설정이나 시작 메뉴를 변경하지 않도록 경로를 분리했다. [설치 명세](installation-and-global-hooks.md)와 [시험 안내](../../CodexPet.Tests/README.md)를 참고한다.

위의 설치 구현 부재에 관한 기록은 2026-11-09 당시의 상태다. 실제 사용자 계정과 다른 계정 간 격리, 실제 Codex의 신뢰·이벤트 흐름, 제거 화면의 실제 선택 조작, 개발 도구 없는 환경과 최종 배포 파일의 전체 보안 검증은 여전히 미완료다. 같은 계정의 파이프 위조·선점 문제에 대한 판단도 남아 있다.
