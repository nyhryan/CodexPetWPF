## 위젯 내 작업 상태 표시

### 목적

사용자가 이 프로젝트에서 실행하는 Codex의 작업 상황을 이미지로 파악할 수 있다.

### 동작 범위

- 첫 버전은 이 프로젝트에 등록된 Codex 훅에서 전달한 이벤트를 수신한다.
- 위젯이 시작되면 대기 상태의 문구와 등록된 이미지가 표시된다. 이미지가 없으면 이미지 영역을 비운다. 이미 진행 중인 작업의 상태는 복구하지 않고, 시작 이후 수신한 이벤트부터 반영한다.
- 수신한 이벤트에 따라 상태와 해당 문구·이미지를 전환한다. 해당 상태에 이미지가 없으면 영역을 비운다. 명세에 없는 이벤트를 받아도 현재 상태를 유지하고 앱은 계속 동작한다.
- 여러 세션을 구분하거나 상태를 집계하지 않는다. 세션 ID와 관계없이 수신한 이벤트를 도착 순서대로 반영한다. 따라서 한 세션의 이벤트가 다른 세션의 상태 표시를 덮어쓸 수 있다.
- 위젯이 꺼져 있거나 이벤트 전달에 실패해도 Codex 작업은 계속된다.

### 상태 전환

| 상태 | 이벤트 | 이미지 예시 |
|---|---|---|
| 대기 | `SessionStart` (`source`가 `compact`가 아닌 경우), `Stop`, `SessionEnd`, `Interrupt` | 편하게 앉아 꼬리를 흔들거나 꾸벅꾸벅 졸기 |
| 의뢰 확인 | `UserPromptSubmit` | 편지를 받아 읽고 눈을 반짝이기 |
| 생각 중 | `PreModelRequest`, `PostModelRequest` | 턱을 괴고 고민하다 머리 위에 전구 켜기 |
| 작업 중 | `PreToolUse`, `PostToolUse` | 키보드를 두드리고 돋보기로 결과 살펴보기 |
| 허락 대기 | `PermissionRequest` | 허가서를 내밀고 사용자 쪽을 바라보기 |

이미지는 사용자가 상태별로 등록한다. 기본 GIF는 포함하지 않으며 자세한 동작은 [사용자 이미지 명세](user-provided-images.md)를 따른다.

- `source`가 `compact`인 `SessionStart`는 현재 상태를 유지한다. 압축 전후 이벤트 등 표에 명시하지 않은 이벤트도 현재 상태를 유지한다.
- 새로운 이벤트가 다른 상태에 해당하면 현재 GIF의 재생을 기다리지 않고 즉시 전환한다. 최소 표시 시간이나 이벤트 재생 대기열은 없다.
- 현재 상태와 같은 상태의 이벤트를 받으면 이미지를 바꾸거나 GIF를 다시 시작하지 않는다. 예를 들어 `PreToolUse` 다음에 `PostToolUse`를 받으면 작업 중 이미지를 계속 재생한다.
- `PostModelRequest`와 `PostToolUse` 이후에는 각각 생각 중과 작업 중을 유지한다. 상태를 바꾸는 다음 이벤트가 오지 않으면 시간 제한 없이 현재 이미지를 유지한다. 의뢰 확인과 허락 대기도 같다.
- `Stop`과 `Interrupt`에서는 별도 완료 GIF 없이 즉시 대기로 전환한다.

`PermissionRequest`는 승인 절차 직전의 신호이므로, 허락 대기 이미지는 실제 승인 화면의 표시나 사용자의 응답을 확정적으로 뜻하지 않는다. 다른 이벤트가 오지 않으면 승인 절차가 끝났더라도 이미지가 유지될 수 있다.

### 2026-11-04 14:53 추가: 위젯 화면 구성

위젯은 위쪽의 캡션과 아래쪽의 상태 이미지로 구성한다. 첨부된 밈 생성기 스크린샷처럼 굵고 폭이 좁은 흰색 대문자를 사용하며, 폰트는 Impact를 사용한다.

- 이미지 영역은 256×256 크기의 정사각형이고, 캡션 영역은 이미지와 같은 너비에 높이는 48이다. 크기는 WPF 화면 단위로 지정한다.
- 캡션과 이미지 사이에는 간격을 두지 않는다. 캡션 배너는 흰색으로, 이미지에서 보이는 배경은 배너와 구분되는 옅은 회색으로 표시한다.
- 캡션은 영문 대문자 Impact를 사용해 가운데 정렬한다. 기본 글자 크기는 40이며 한 줄로 표시한다. 문구와 테두리가 영역에 들어가지 않으면 크기를 줄여 전체가 보이게 한다.
- 글자는 흰색으로 채우고 글자 주변에 선명한 검은색 테두리를 적용한다. 테두리 두께는 보이는 대문자 글자 높이의 약 1/15로 한다. 글자 뒤의 그림자는 적용하지 않는다.
- 기존에 앱에 포함했던 Inter 폰트 파일과 관련 리소스 참조를 제거한다. Impact는 Windows에 설치된 시스템 글꼴을 사용하며 폰트 파일을 앱에 포함하지 않는다. Impact가 설치되지 않은 환경에서는 다른 글꼴로 대체될 수 있다.
- 상태가 바뀌면 아래 캡션을 해당 이미지와 함께 전환한다. 상태 전환 규칙과 기존 드래그·우클릭 종료 동작은 유지한다.

| 상태 | 캡션 |
|---|---|
| 대기 | `AURA FARMING` |
| 의뢰 확인 | `CHAT WHAT IS THIS` |
| 생각 중 | `LOWKEY COOKING RN` |
| 작업 중 | `LOCKED IN FR` |
| 허락 대기 | `JUST HIT APPROVE` |

허락 대기 캡션은 밈 문구이며 실제 승인 화면의 표시나 사용자 응답 여부를 확정하지 않는다.

### 완료 기준

- 캡션이 이미지 영역 위에 표시되고, 상태에 따라 위 표의 문구와 등록된 이미지가 바뀐다. 이미지가 없는 상태는 영역을 비운다.
- 캡션은 Impact의 흰색 영문 대문자와 글자 높이의 약 1/15인 검은 테두리로 한 줄에 표시하며, 그림자는 없다. 길면 크기를 줄여 전체 문구와 테두리가 보인다.
- 흰색 캡션 배너와 옅은 회색 이미지 배경이 구분되고, 크기는 위 화면 구성 조건을 따른다.
- 기존 Inter 폰트 파일과 리소스 참조가 제거되고 Impact가 사용된다.
- 위젯 시작 시 대기 상태의 문구와 등록된 이미지가 표시되고, 이후 수신한 이벤트에 따라 해당 상태를 표시한다. 등록된 이미지가 없으면 영역을 비운다.
- `UserPromptSubmit` 다음에 `PreModelRequest`, `PreToolUse`가 이어지면 각 이미지를 재생 완료까지 기다리지 않고 순서대로 전환한다. 후속 이벤트가 없으면 마지막 상태를 유지한다.
- `PreModelRequest` 다음 `PostModelRequest`, `PreToolUse` 다음 `PostToolUse`를 받으면 각각 같은 GIF를 다시 시작하지 않는다.
- `PermissionRequest`를 받으면 허락 대기를 표시하고, 상태를 바꾸는 다음 이벤트가 오기 전까지 유지한다.
- `source: compact`인 `SessionStart`와 명세에 없는 이벤트는 현재 이미지를 유지하며 앱을 종료하지 않는다. 그 외의 `SessionStart`, `Stop`, `SessionEnd`, `Interrupt`는 대기 상태로 전환한다.
- 서로 다른 세션의 이벤트라도 수신 순서대로 처리하며, 세션별 우선순위나 별도 상태를 적용하지 않는다.
- 사용자가 등록한 상태별 이미지가 앱에서 표시되고, 위젯이 꺼져 있거나 이벤트 전달에 실패해도 Codex 작업이 계속된다.

### 구현 시 확인할 사항

- 실제 Codex 환경에서 요청, 모델 요청, 도구 실행, 승인·거부, 중단, 압축 및 서브에이전트 이벤트의 순서와 필요한 필드를 확인한다. 확인 전에는 특정 후속 이벤트가 반드시 온다고 가정하지 않는다.
- 현재 훅 실행기의 빈 표준 출력이 `Stop`과 `SubagentStop`에서 문제없이 처리되는지 확인한다.
- 기본 GIF가 빌드에 포함되지 않는지와 사용자가 등록한 GIF의 실제 재생을 검증한다.
- [Microsoft 글꼴 재배포 안내](https://learn.microsoft.com/en-us/typography/fonts/font-faq)에 따라 Impact 시스템 글꼴을 사용하고 폰트 파일을 재배포하지 않는다.
- 이미지의 투명한 부분과 이미지가 없는 영역에는 옅은 회색이 보인다.
- 위젯의 글자 모양, 테두리 두께와 배경 대비를 화면에서 확인한다.
