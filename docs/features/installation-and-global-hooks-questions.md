# Spec 2. 설치·삭제와 전역 훅 연동: 결정할 질문

이 문서는 [Spec 2 초안](installation-and-global-hooks.md)을 완성하기 위한 질문입니다. 각 질문의 원하는 `[ ]`를 `[x]`로 바꾸거나 `1-A, 2-B, 3-A ...`처럼 번호와 선택지만 알려주세요. **“추천대로”**라고 답하거나 다른 의견을 직접 적어도 됩니다. 각 추천은 제안이며 아직 결정된 내용이 아닙니다.

이미 정해진 범위는 **Windows 11 x64 로컬 Codex**, **Inno Setup 설치 파일**, **서명 없는 0.1.0 준비**입니다. 모든 경우에 다른 프로그램의 훅과 다른 Windows 사용자의 설정은 보존하고, 위젯이 꺼져 있어도 Codex 작업이 계속되도록 합니다.

## 1. 어디에 설치할까요?

설치 파일에 사용자 이름을 고정하지 않고 해당 PC의 실제 경로를 사용합니다. 사용자별 설치는 보통 관리자 권한 없이 진행할 수 있지만 실제 환경에서 확인해야 합니다.

- [x] **A. 현재 Windows 사용자에게만 설치하고 위치는 고정합니다.** `%LOCALAPPDATA%\CodexPet` 아래에서 앱·훅과 사용자 데이터를 구분해 둡니다. **추천: 설치·삭제와 경로 관리를 단순하게 시작할 수 있습니다.**
- [ ] B. 현재 사용자에게만 설치하고 사용자가 앱·훅의 설치 경로를 바꿀 수 있습니다. 설정·이미지·로그의 위치는 별도로 안내합니다. 경로 변경과 업데이트 시험이 추가됩니다.
- [ ] C. 모든 Windows 사용자에게 설치합니다. 관리자 권한과 사용자별 Codex 설정 등록·제거 범위를 별도로 설계해야 합니다.
- [ ] D. 직접 정하기: ___

## 2. Windows 로그인 시 자동으로 시작할까요?

자동 시작은 사용자 계정의 시작프로그램 바로 가기로 제공하는 방향입니다. 설치 후 위젯은 우클릭 메뉴로 종료할 수 있습니다.

- [ ] **A. 선택 항목으로 제공하고 처음에는 꺼 둡니다.** 사용자가 원하면 설치 화면에서 켭니다. **추천: 로그인 시 자동 실행을 사용자가 직접 선택합니다.**
- [ ] B. 선택 항목으로 제공하고 처음에는 켜 둡니다. 사용자가 설치 화면에서 끌 수 있습니다.
- [ ] C. 항상 자동 시작합니다. 설정을 바꾸는 방법을 별도로 안내해야 합니다.
- [x] D. 설치 중 선택하지 않고 자동 시작을 제공하지 않습니다.
- [ ] E. 직접 정하기: ___

재설치·업데이트에서는 가능하면 이전 자동 시작 선택을 유지하고, 이전 선택을 알 수 없다면 위 기본값을 적용하는 방향을 제안합니다. 다르게 원하면 적어 주세요: ___

## 3. 설치가 끝나면 위젯을 바로 실행할까요?

훅은 사용자가 Codex에서 검토·신뢰해야 하므로 위젯이 실행되었다는 사실만으로 이벤트 수신이 보장되지는 않습니다.

- [ ] **A. 설치 완료 화면에 ‘CodexPet 실행’ 선택을 제공하고 처음에는 켜 둡니다.** 사용자가 끌 수 있습니다. **추천: 설치 직후 화면을 확인하기 쉽습니다.**
- [ ] B. 같은 선택을 제공하되 처음에는 꺼 둡니다.
- [ ] C. 자동으로 실행하고 선택 항목은 제공하지 않습니다.
- [x] D. 자동 실행하지 않습니다. 시작 메뉴 등에서 직접 실행하도록 안내합니다.
- [ ] E. 직접 정하기: ___

## 4. 기존 훅 설정을 읽거나 저장할 수 없으면 어떻게 할까요?

예를 들어 기존 `hooks.json`이 잘못된 JSON이거나 쓰기 권한이 없을 수 있습니다. 어떤 선택이든 원본 파일과 다른 훅을 덮어쓰지 않고 문제와 복구 방법을 안내합니다.

- [x] **A. 훅 등록까지 성공해야 설치가 완료된 것으로 처리합니다.** 실패하면 남은 상태와 복구·재시도 방법을 안내합니다. **추천: 설치 완료 화면이 실제 연동 상태와 일치합니다.**
- [ ] B. 앱은 설치하되 ‘훅 등록 실패’라고 명확히 알리고, 복구 후 다시 등록할 수 있는 방법을 제공합니다. 등록 전에는 다른 프로젝트의 이벤트를 받지 못합니다.
- [ ] C. 직접 정하기: ___

A를 선택해도 오류 시 이미 복사된 파일이 무조건 사라진다고 가정하지 않습니다. 복구·정리와 재시도 동작은 구현하고 검증해야 합니다.

## 5. 제거할 때 훅 설정을 정리할 수 없으면 어떻게 할까요?

설정이 손상되었거나 권한이 없으면 CodexPet 항목을 안전하게 지우지 못할 수 있습니다. 실행 파일만 삭제하면 남은 훅이 없는 파일을 가리킬 수 있습니다.

- [x] **A. 훅 정리가 실패하면 제거를 멈추고 복구 후 다시 시도하도록 안내합니다.** 다른 훅은 그대로 보존합니다. **추천: 실행 파일이 없는 경로를 훅에 남길 가능성을 줄입니다.**
- [ ] B. 훅 정리에 실패해도 앱 제거를 계속할 수 있게 합니다. 남은 항목의 위치와 수동 제거 방법을 분명히 안내합니다.
- [ ] C. 직접 정하기: ___

## 6. 앱을 제거할 때 내 데이터는 어떻게 할까요?

사용자 데이터에는 설정한 문구와 **CodexPet이 보관하는 이미지 사본**, 새 진단 로그와 이전 진단 로그가 있습니다. 원래 선택했던 이미지 파일은 삭제 대상이 아닙니다. 이전 로그에는 세션 ID 등이 남아 있을 수 있습니다.

- [x] **A. 기본적으로 모두 보존하고, 사용자가 삭제할 항목을 따로 선택할 수 있게 합니다.** 설정·이미지 사본, 새 로그, 이전 로그를 구분하고 삭제 전 대상을 안내합니다. **추천: 재설치에 대비하면서 불필요한 데이터는 직접 지울 수 있습니다.**
- [ ] B. 항상 모두 보존하고 위치와 수동 삭제 방법을 안내합니다. 제거 화면에는 데이터 삭제 선택을 두지 않습니다.
- [ ] C. 기본적으로 보존하되 설정·이미지 사본만 삭제 선택을 제공합니다. 새 로그와 이전 로그는 수동으로 삭제합니다.
- [ ] D. 직접 정하기: ___

어떤 선택이든 Spec 3에 따라 **이전 로그는 자동 삭제하지 않습니다**. A에서 이전 로그를 지우는 경우에도 사용자가 그 항목을 명시적으로 선택해야 합니다. 선택하지 않은 설정·이미지와 로그, 원본 이미지 및 다른 프로그램의 파일은 보존합니다.

## 7. 재설치나 업데이트 중 위젯이 실행 중이면 어떻게 할까요?

실행 중인 파일을 교체하려면 위젯을 종료해야 할 수 있습니다. 재설치·업데이트는 다른 훅과 사용자 데이터, 가능한 경우 이전 자동 시작 선택을 보존합니다.

- [x] **A. 실행 중임을 알리고 사용자가 종료한 뒤 다시 시도하도록 합니다.** **추천: 첫 버전의 동작과 복구 과정을 단순하게 유지합니다.**
- [ ] B. 설치 화면에서 종료 여부를 확인하고 동의하면 위젯을 종료한 뒤 계속합니다. 완료 후 다시 실행할지도 선택합니다.
- [ ] C. 별도 확인 없이 설치 프로그램이 종료하고 완료 후 다시 실행합니다.
- [ ] D. 직접 정하기: ___

## 8. 기본 위치가 아닌 Codex 설정 폴더도 지원할까요?

보통 사용자 홈의 `.codex`를 사용하지만, 별도 Codex 홈이나 프로필을 쓰는 환경에서는 실제로 읽는 설정 위치가 다를 수 있습니다. 지원 여부와 위치 확인 방법은 대상 Codex 버전에서 시험해야 합니다.

- [x] **A. 첫 버전은 기본 사용자 홈의 `.codex`만 설정합니다.** 다른 위치를 쓰는 사용자는 자동 연동이 보장되지 않음을 안내하고 수동 설정 방법을 제공합니다. **추천: 첫 검증 범위를 명확히 합니다.**
- [ ] B. 설치 중 사용할 Codex 설정 폴더를 선택할 수 있게 합니다. 선택한 폴더와 실제 Codex가 읽는 위치를 확인하고 재설치·제거에도 같은 위치를 사용해야 합니다.
- [ ] C. 다른 Codex 홈을 자동으로 감지해 설정합니다. 감지 기준, 여러 환경의 우선순위와 실제 동작을 확인해야 합니다.
- [ ] D. 직접 정하기: ___

## 9. 이 저장소의 개발용 프로젝트 훅과 전역 훅이 겹치면 어떻게 할까요?

이 저장소의 `.codex/hooks.json`은 개발용입니다. 사용자 전역 훅과 함께 켜 두면 같은 이벤트에 훅이 두 번 실행될 수 있습니다. 설치 프로그램이 임의로 프로젝트 설정을 수정하면 다른 개발 환경에 영향을 줄 수 있습니다.

- [ ] **A. 설치 프로그램은 프로젝트 파일을 수정하지 않고 중복 가능성과 수동 정리 방법을 안내합니다.** **추천: 사용자의 프로젝트 설정을 임의로 바꾸지 않습니다.**
- [ ] B. 개발 환경에서 전역 설치를 사용하도록 별도 변경을 진행합니다. 어떤 파일을 언제 바꿀지는 실제 구현 시 확인합니다.
- [x] C. 직접 정하기: 내가 이 저장소 내 훅을 구현 이전에 지울테니 걱정할 필요 없음.

## 답변 후 확정할 내용

- 사용자별 설치 위치와 권한, 설치 후 실행 및 자동 시작 기본값.
- 기존 훅 파일이 없거나 손상·잠김·권한 부족인 경우의 설치·제거 결과와 복구 방법.
- 제거할 때 사용자 문구·이미지 사본, 새 로그와 이전 로그의 보존·삭제 흐름.
- 재설치·업데이트 시 실행 중인 위젯, 이전 자동 시작 선택, 훅 중복과 경로 변경 처리.
- 기본이 아닌 Codex 홈과 개발용 프로젝트 훅의 지원 및 안내 범위.

답변을 반영한 뒤 소유한 훅을 식별하는 방식과 실제 Codex 설정·셸 호환성을 설계하고 격리된 환경에서 검증합니다. 이 질문지는 설치나 실제 설정 변경을 수행하지 않습니다.
