# Spec 4. 0.1.0 릴리스 준비: 결정할 질문

이 문서는 [Spec 4 초안](release-validation-and-distribution.md)을 확정하기 위한 질문입니다. 각 질문에서 원하는 `[ ]`를 `[x]`로 바꾸거나 `1-A, 2-B ...`처럼 답해 주세요. **“추천대로”**라고 답하거나 다른 의견을 적어도 됩니다. 추천은 확정된 정책이 아닙니다. 지금 모르는 환경 정보는 “아직 없음”이라고 답해도 됩니다.

이미 결정한 **Windows 11 x64 로컬 Codex, 공개 GitHub Releases, 미서명 설치 파일, 같은 계정의 파이프 위조·선점 위험 수용**은 다시 묻지 않습니다. 선택만으로 시험에 통과하거나 공개가 승인되는 것은 아닙니다.

## 1. 개발 도구 없는 Windows 시험 환경을 어떻게 마련할까요?

실제 설치 파일에 필요한 런타임이 들어 있는지 확인하려면 별도 SDK·.NET 런타임이 없는 환경이 필요합니다. Windows 기본 구성 요소를 임의로 삭제할 필요는 없습니다.

- [ ] **A. 별도 Windows 11 x64 PC 또는 VM을 준비해 시험합니다. 추천** — 실제 환경 정보와 준비 가능 시점을 아래에 적어 주세요.
- [x] B. 그런 환경을 아직 마련할 수 없습니다. 미검증으로 남기고 환경이 준비될 때까지 최종 승인 판단을 기다립니다.
- [ ] C. 다른 계획: ___

훅 신뢰, 실제 화면 확인, 제거 선택은 시험 환경에서 직접 조작해야 할 수 있습니다. 시험에는 실제 설정 대신 별도 계정이나 합성 자료를 사용합니다.

- [ ] **A. 가능한 자동·격리 검사는 에이전트가 하고, 실제 화면과 Codex 시험은 제가 수행합니다. 추천**
- [ ] B. 준비된 시험 환경에서 에이전트가 가능한 실제 화면 시험까지 수행하고, 필요한 경우에만 제가 조작합니다.

## 3. 기존 훅과 다른 Windows 계정 시험 환경이 있나요?

다른 프로그램의 훅 보존과 다른 계정의 파이프 접근은 합성 설정과 격리된 계정으로 확인할 수 있습니다. 실제 개인 설정이나 다른 사람의 계정을 변경할 필요는 없습니다.

- [ ] **A. 격리된 시험 계정과 합성 훅을 준비할 수 있습니다. 추천** — 다른 계정·권한 수준도 가능한 범위를 기록해 주세요.
- [ ] B. 합성 훅은 준비할 수 있지만 별도 계정·권한 수준은 아직 어렵습니다. 해당 시험은 미검증으로 남깁니다.
- [ ] C. 아직 둘 다 준비하기 어렵습니다. 가능한 환경과 일정부터 정합니다.

## 4. 설치·사용 중 문제가 생겼을 때 어디로 문의하도록 안내할까요?

공개 릴리스에서 사용자가 접근할 수 있는 연락 방법이 필요합니다. 로그를 요청한다면 개인 정보가 있을 수 있는 이전 로그를 포함해 공개 전에 사용자가 내용을 확인하도록 안내합니다.

- [x] **A. 공개 GitHub 저장소의 Issues를 사용합니다. 추천** — 이슈 사용 여부와 비로그인 열람 가능성은 공개 전에 확인합니다.
- [ ] B. 다른 문의처를 사용합니다. 이름과 주소: ___
- [ ] C. 아직 정하지 않았습니다. 릴리스 안내를 완성하기 전에 정합니다.

## 5. 최종 공개를 누가 결정하고 진행할까요?

같은 계정의 파이프 위험에 대한 수용은 이미 결정됐습니다. 이 질문은 그 밖의 미검증 항목과 최종 파일을 포함한 **전체 릴리스**에 관한 것입니다.

- [x] **A. 제가 검사 결과를 보고 승인하며, 승인 후 에이전트가 GitHub Releases 공개 작업을 진행합니다. 추천**
- [ ] B. 제가 결과를 보고 승인한 뒤 직접 공개합니다. 에이전트는 파일과 안내를 준비합니다.
- [ ] C. 다른 판단자 또는 방식: ___

검증 결과 차단 문제나 미검증 항목이 남으면 영향과 가능한 조치를 먼저 보고합니다. 이 답변은 지금 당장의 공개 승인이 아닙니다.

- 결과 기록과 문의 안내, 최종 승인 및 공개 작업의 담당자.
