# 상태 표시 기능: 구현 전 질문

이 문서는 [상태 표시 명세](show-state-widget.md)를 구현하기 전에 결정할 내용을 모은 것이다. 각 질문에서 원하는 항목의 `[ ]`를 `[x]`로 바꾸거나, 항목 번호와 답을 알려주면 된다. 추천은 논의를 시작하기 위한 제안이며 아직 결정된 내용은 아니다.

## 확인된 사실

- 현재 [명세](show-state-widget.md)에 적힌 훅은 모두 [OpenAI 공식 훅 문서](https://learn.chatgpt.com/docs/hooks)에 있다. 이 PC의 기존 훅 로그에서도 각 이벤트 이름이 확인됐다. 다만 이번 조사에서는 이벤트를 새로 발생시켜 전체 흐름을 시험하지 않았다.
- `PreModelRequest`와 `PostModelRequest`는 모델 요청의 시작과 결과를 나타내고, 재시도할 때도 발생할 수 있다. `PreToolUse`와 `PostToolUse`도 각각 도구 실행 전과 실행 후에 발생한다.
- `PermissionRequest`는 승인 절차 직전에 발생한다. 다른 훅의 결정으로 실제 사용자 승인 화면이 나타나지 않을 수도 있다.
- `SessionStart`는 새 세션 시작 외에 재개나 컨텍스트 압축 후에도 발생할 수 있다. 압축과 서브에이전트에도 별도의 훅이 있다.
- 현재 프로토타입은 파이프로 이벤트를 받지만, GIF 매핑과 시작 이미지가 명세와 다르며 세션별 상태를 추적하지 않는다. 다섯 GIF 파일은 있으나 일부 리소스 등록과 기존 파일 참조를 확인해야 한다.

## 답변할 질문

### 1. 의뢰 확인 이미지는 얼마나 보여줄까?

사용자 요청을 받으면 `receive.gif`를 표시한다. 바로 다음 이벤트가 들어오면 이미지가 거의 보이지 않을 수 있다.

- [X] **A. 다음 이벤트가 오면 즉시 전환** — 실제 상태를 빠르게 반영한다. **추천**
- [ ] B. 최소 시간을 채운 후 전환 — 다음 이벤트가 와도 잠깐 보여준다. 최소 시간: ___초
- [ ] C. GIF를 한 번 끝까지 재생한 뒤 전환
- [ ] D. 직접 정하기: ___

다음 이벤트가 오지 않을 경우:

- [X] E. 다음 이벤트가 올 때까지 유지 **추천**
- [ ] F. ___초 후 대기로 전환
- [ ] G. 직접 정하기: ___

### 2. 연속 이벤트가 오면 어떻게 표시할까?

예를 들어 의뢰 확인 GIF가 끝나기 전에 생각 중, 작업 중 이벤트가 차례로 들어올 수 있다.

- [X] **A. 새 이벤트를 즉시 반영** — 이전 이미지는 중간에 끝날 수 있다. **추천**
- [ ] B. 현재 일시 동작을 마친 뒤 가장 최근 상태만 표시 — 중간 상태는 생략할 수 있다.
- [ ] C. 들어온 일시 동작을 순서대로 모두 재생 — 실제 상태보다 표시가 늦어질 수 있다.
- [ ] D. 직접 정하기: ___

1번에서 최소 시간이나 한 번 재생을 선택한 경우에는 B 또는 C처럼 대기 중인 이벤트를 어떻게 처리할지도 골라 주세요. `Interrupt`처럼 우선 처리할 예외가 있다면: ___

### 3. 요청·도구 실행이 끝난 뒤에는 무엇을 보여줄까?

현재 명세는 시작과 종료 이벤트를 같은 이미지에 연결한다. 예를 들어 `PreToolUse`와 `PostToolUse` 모두 작업 중이다.

- [X] **A. 현재 명세대로 종료 이벤트에서도 같은 상태를 유지하고 다음 이벤트를 기다린다.** **추천**
- [ ] B. 종료 이벤트마다 다른 상태로 전환한다. `PostModelRequest` 다음: ___ / `PostToolUse` 다음: ___
- [ ] C. 직접 정하기: ___

어떤 선택이든 같은 상태의 이벤트가 연속으로 오면 GIF를 다시 시작하지 않는 것이 현재 명세다.

### 4. 승인 요청 이미지는 언제까지 보여줄까?

`PermissionRequest`는 승인 절차 직전의 신호다. 승인 화면이 실제로 표시되었는지, 사용자가 응답했는지를 이 훅 하나만으로는 확정할 수 없다.

- [X] **A. 다음 상태 이벤트가 오면 전환한다.** 후속 이벤트가 없으면 유지한다. **추천**
- [ ] B. 다음 상태 이벤트가 오면 전환하고, 이벤트가 없으면 ___초 후 대기로 바꾼다. 실제로 아직 승인 대기 중이어도 대기로 보일 수 있다.
- [ ] C. 실제 승인 화면과 응답을 감지할 방법을 먼저 조사하고 그 결과에 따라 정한다. 구현 범위와 가능 여부는 아직 미확인이다.
- [ ] D. 직접 정하기: ___

### 5. 여러 Codex 세션이 동시에 있으면 무엇을 보여줄까?

예를 들어 한 세션은 작업 중이고 다른 세션은 승인 절차 중일 수 있다.

- [X] **A. 가장 최근에 도착한 이벤트의 상태를 표시한다.** 단순하지만 다른 세션의 승인 대기를 놓칠 수 있다. **추천: 첫 버전을 단순하게 시작할 때**
- [ ] B. 세션별 상태를 추적하고 우선순위로 하나를 표시한다. 예: 허락 대기 > 작업 중 > 생각 중 > 의뢰 확인 > 대기. 세션별 상태 종료와 서브에이전트 집계 규칙이 추가로 필요하다.
- [ ] C. 한 세션만 표시한다. 선택 기준: ___
- [ ] D. 직접 정하기: ___

### 6. 명세에 연결되지 않은 이벤트는 어떻게 처리할까?

현재 명세는 모든 미지정 이벤트에서 대기로 전환한다. 그러나 압축이나 서브에이전트 관련 이벤트는 작업 도중에도 발생할 수 있다.

- [X] **A. 현재 상태를 유지한다.** 알 수 없는 이벤트를 받아도 앱은 계속 실행한다. **추천**
- [ ] B. 현재 명세대로 대기로 전환한다. 작업 중에도 잠깐 대기로 표시될 수 있다.
- [ ] C. 이벤트별로 다르게 처리한다. 규칙: ___

또한 `SessionStart`는 작업 도중 압축 후에도 발생할 수 있다.

- [ ] D. 발생 이유와 관계없이 대기로 전환한다. **현재 명세**
- [X] E. 압축 후 발생한 `SessionStart`는 현재 상태를 유지한다. **추천**
- [ ] F. 직접 정하기: ___

### 7. “작업이 끝났을 때 GIF를 잠깐 보여준다”는 어떤 의미일까?

현재 명세에는 어떤 완료 이벤트에서 어떤 GIF를 얼마나 보여주고 그다음 무엇을 표시할지가 정해져 있지 않다.

- [X] **A. 첫 버전에서는 별도 완료 동작 없이 `Stop`에서 바로 대기 이미지를 보여준다.** **추천**
- [ ] B. 완료 이미지를 잠깐 보여준 뒤 대기로 전환한다. 사용할 파일: ___ / 표시 시간 또는 반복 횟수: ___
- [ ] C. 직접 정하기: ___

`Interrupt`는 현재 명세대로 별도 완료 동작 없이 대기로 돌아간다. 다르게 원한다면: ___

### 8. 첫 버전에서 어느 Codex 작업을 표시할까?

현재 훅은 이 프로젝트에 등록되어 있다. 다른 프로젝트까지 표시하려면 등록과 신뢰 방법을 따로 마련해야 한다.

- [X] **A. 우선 이 프로젝트에서 실행한 Codex 작업만 표시한다.** **추천**
- [ ] B. 이 Windows 사용자 계정의 다른 프로젝트 작업도 표시한다. 설치·등록 방법을 함께 결정해야 한다.
- [ ] C. 직접 정하기: ___

위젯을 작업 도중 켰을 때 현재 상태를 바로 알 수 있는지는 아직 확인되지 않았다.

- [X] D. 시작 시 대기를 표시하고 이후 수신한 이벤트부터 반영한다. **추천**
- [ ] E. 실행 중인 작업의 현재 상태를 복구할 방법을 먼저 조사한다.

## 구현 전 실제 환경에서 확인할 항목

아래는 사용자가 선택해야 하는 기능 정책이 아니라, 구현 전에 재현하거나 점검할 사항이다. 결과에 따라 위 답변을 다시 검토할 수 있다.

- [ ] 훅이 신뢰·활성화된 상태에서 요청 제출 → 모델 요청 → 도구 실행 → 완료의 실제 이벤트 순서와 필드를 확인한다.
- [ ] 승인 요청을 허용하거나 거부했을 때 후속 이벤트가 무엇인지, 승인 화면이 생략되는 경우가 있는지 확인한다.
- [ ] 중단, 컨텍스트 압축, 서브에이전트와 동시 세션에서 어떤 이벤트와 식별자가 전달되는지 확인한다.
- [ ] 현재 실행기의 빈 표준 출력이 `Stop`과 `SubagentStop`에서 문제없이 처리되는지 확인한다. 공식 문서는 일반 성공 출력과 이벤트별 출력에 관해 확인이 필요한 설명을 포함한다.
- [ ] GIF 다섯 개를 리소스로 사용할 수 있도록 현재 프로젝트 설정을 확인하고, 빌드 및 실제 재생을 검증한다.
- [X] 위젯이 꺼져 있거나 이벤트 전달에 실패해도 Codex 작업이 계속되는지 확인한다.

## 기타사항

- 여러 세션이 존재하는 경우, 지금 구현에서는 날라오는 이벤트만 보고 이미지를 전환한다. 다중 세션은 고려하지 않는다.
