# Spec 1. Windows 배포 패키지와 빌드

## 상태

**답변 반영 — 구현 전 명세.** [결정할 질문](windows-distribution-package-questions.md)에 표시된 답변을 반영했다. 이 문서는 배포물이나 설치 프로그램이 이미 만들어졌다는 뜻이 아니다.

## 목적

개발 환경이 없는 친구도 CodexPet을 설치하고 실행할 수 있도록, 0.1.0 Windows 배포물을 문서화된 절차로 만들고 전달한다. 개발자는 같은 소스 버전과 명시된 도구·설정으로 같은 구성의 배포물을 다시 만들 수 있어야 한다. 여기서 재현 가능은 동일한 절차와 구성의 결과를 뜻하며, 파일의 해시까지 매번 동일함을 요구하지는 않는다.

## 현재 확인된 내용

- 앱 `CodexPet.App`은 `net10.0-windows` WPF 프로젝트이고, 훅 실행기 `CodexPet.Hook`은 `net10.0` 프로젝트다. 앱은 Release 구성에서 Windows GUI 실행 파일로 빌드된다.
- 개발용 프로젝트 훅은 사용자가 `hooks.json.bak`으로 변경해 비활성화했다. Spec 2의 설치 프로그램과 전역 훅 등록·삭제 구현이 추가되었으며 실제 배포 환경 검증은 아직 완료되지 않았다. 배포 자동화는 이 Spec에서 다룬다.
- [기존 검증 안내](../../CodexPet.Tests/README.md)는 현재 상태 전환과 개발용 훅·파이프 연동을 확인하지만, 설치 패키지나 개발 도구가 없는 환경을 검증하지는 않는다.

## 범위

- 첫 배포 대상은 **Windows 11 x64에서 실행되는 로컬 Codex**다. 정확한 Windows 11 버전과 에디션은 실제 검증 환경 및 [.NET 지원 범위](https://learn.microsoft.com/en-us/dotnet/core/install/windows)를 확인해 명시한다.
- Windows 10, ARM64, WSL, 원격 환경과 클라우드 작업은 첫 버전의 지원 범위에서 제외한다.
- 앱과 훅을 각각 `Release`, `win-x64`, self-contained로 게시하고, 두 게시 결과와 필요한 의존성을 배포물에 포함한다. 대상 PC에 .NET SDK나 런타임을 별도 설치하지 않도록 하기 위한 것이다. 게시 결과에 .NET의 모든 네이티브 OS 의존성이 포함된다는 뜻은 아니며 지원 OS에서 검증한다. [Microsoft: .NET 게시 방식](https://learn.microsoft.com/en-us/dotnet/core/deploying/)
- Inno Setup으로 Windows 설치 파일 하나를 만든다. 포터블 ZIP은 이번에 제공하지 않는다.
- 자동 업데이트, 다른 OS용 패키지, 클라우드 중계는 이번 범위에서 제외한다. 앱과 훅의 실제 업데이트·재설치 동작은 Spec 2에서 다룬다.

## 배포물 구성과 빌드

1. 개발자 Windows PC에서 문서화된 명령으로 빌드한다. 대상 소스 버전, .NET SDK 버전, Inno Setup 버전과 필요한 빌드 환경을 기록한다. 의존성 복원 방법과 네트워크 필요 여부도 빌드 절차에 명시한다.
2. 앱과 훅을 각각 지정된 게시 폴더에 게시한다. 폴더를 분리해 각 결과의 실행 파일, 런타임, 의존성과 리소스를 빠짐없이 패키징한다. 특정 게시 명령과 실제 폴더 경로는 구현 후 재실행 가능한 형태로 기록한다.
3. 게시 결과의 필요한 앱 리소스와 훅 실행 파일이 포함되었는지 확인하고, Inno Setup으로 설치 파일을 만든다. 기존 Tenor GIF와 로컬 `assets`의 개인 이미지는 포함하지 않는다. 이미지가 없는 상태의 동작은 [사용자 이미지 명세](user-provided-images.md)를 따른다.
4. 빌드 실패, 의존성 복원 실패 또는 패키징 실패 시 성공한 배포물처럼 안내하지 않는다. 실패 단계와 재시도 방법을 빌드 절차에 기록한다.
5. 빌드 주체, 실행 명령, 중간 결과물과 최종 결과물의 위치, 정리 방법을 문서화한다. CI 자동화는 이번 범위에 포함하지 않고 나중에 검토한다.

## 버전과 결과물

- 첫 제품 버전은 `0.1.0`이다. 프로젝트에서 공통으로 읽는 한 곳에 버전을 두고, 앱과 훅의 제품 버전, 설치 프로그램에 표시되는 버전과 결과물 이름에 일관되게 반영한다. 공통 버전의 구체적인 파일 위치와 갱신 방법은 구현 시 정해 문서화한다.
- 설치 파일 이름의 기본 제안은 `CodexPet-Setup-0.1.0-win-x64.exe`다. 빌드 결과를 둘 폴더는 구현 시 정해 문서화하며, 개발자별 절대 경로를 배포물 이름이나 빌드 절차에 고정하지 않는다.
- 최종 설치 파일의 SHA-256 해시와 확인 방법을 제공한다. 해시는 파일이 기대한 값과 같은지 비교하는 수단이며, 해시만으로 배포자의 신원을 증명하지는 않는다. [Spec 3](security-review-and-hardening.md)에 따라 0.1.0은 우선 코드 서명 없이 준비한다.
- self-contained 배포에 포함된 .NET 런타임은 PC의 별도 런타임 업데이트만으로 자동 갱신되지 않는다. 이후 런타임 보안 업데이트를 반영하려면 새 배포물을 만드는 절차가 필요하다. [Microsoft: .NET 게시 방식](https://learn.microsoft.com/en-us/dotnet/core/deploying/)

## 프로젝트와 외부 구성 요소의 라이선스

- CodexPet 자체 소스 코드와 배포물에 적용할 프로젝트 라이선스는 아직 정하지 않았다. 권리자가 이용·수정·재배포 허용 범위를 선택한 뒤 해당 라이선스와 저작권 고지를 저장소와 배포물에 명시한다. 라이선스 종류는 이 명세에서 미리 확정하지 않는다.
- 앱, 훅과 설치 파일에 실제 포함되는 외부 패키지, 추이 의존성, self-contained .NET 구성 요소 및 기타 배포 리소스의 출처·버전·라이선스·필요 고지를 확인하고 목록으로 정리한다. 빌드에만 쓰는 도구의 사용 조건도 별도로 확인한다.
- 현재 직접 참조하는 `XamlAnimatedGif` 2.3.2는 NuGet에서 Apache-2.0으로 표시한다. 해당 버전의 라이선스 사본과 적용되는 저작권·NOTICE 등 고지를 확인해 필요한 내용을 배포물에 제공한다. [NuGet 패키지 정보](https://www.nuget.org/packages/XamlAnimatedGif/2.3.2), [Apache License 2.0](https://www.apache.org/licenses/LICENSE-2.0)
- 설치된 앱 또는 함께 제공하는 문서에서 사용자가 프로젝트 라이선스와 필요한 외부 구성 요소 고지를 확인할 수 있게 한다. 고지 파일의 구체적인 형식과 위치는 각 라이선스 조건을 확인해 정하고 빌드 절차에 기록한다.
- 기존 Tenor GIF는 권리 허락을 전제로 하지 않으며 앱과 설치 파일에 포함하지 않는다. 사용자가 직접 가져온 이미지는 사용자의 로컬 설정으로 취급한다. 이미지별 이용 권한은 별도로 확인해야 한다.
- 실제 배포물에서 누락된 고지가 없는지 검증한다. Spec 3의 의존성 점검과 연결하고 Spec 4의 최종 설치 파일 검증에도 결과를 반영한다.

## 전달과 안내

- GitHub Releases에 누구나 받을 수 있도록 공개한다. 이 Spec은 채널과 배포물 구성·초안 작성 방법을 정의하며, 실제 공개와 릴리스 승인은 Spec 4에서 한다. 사용할 저장소의 공개 설정과 릴리스 접근 가능 여부는 공개 전에 확인한다.
- 배포 안내에는 지원 Windows 환경, 다운로드 파일명, 설치·삭제 안내 위치, 로컬 Codex 지원 범위, 알려진 제한, 버전과 변경 사항, 해시 확인 방법을 포함한다. 훅 검토·신뢰와 문제 해결 안내는 Spec 2·4의 결과를 반영한다.
- 설치 파일이 서명되지 않았음을 밝히고, 사용자에게 나타날 수 있는 Windows 경고에 대한 안내를 릴리스 전에 준비한다. [Spec 3](security-review-and-hardening.md)의 다운로드 출처와 해시 확인 안내도 반영한다.

## 다른 Spec과의 관계

- **Spec 2 — 설치·삭제와 전역 훅 연동:** 설치 위치, 기존 설정 보존과 훅 등록·삭제, 자동 시작, 업데이트 및 사용자 안내를 정의하고 구현한다. Spec 1은 그 결과를 포함할 패키징과 빌드 절차를 다룬다. 설치 프로그램의 실제 동작과 최종 설치 성공은 Spec 2에 의존한다.
- **Spec 3 — 보안 점검 및 개선:** 파이프·로그, 설치 과정, 의존성, 배포물 무결성과 서명 여부를 점검한다. 보안 점검에서 결정한 패키징 요구사항을 Spec 1에 반영한다.
- **Spec 4 — 릴리스 검증과 배포:** Spec 1·2·3의 결과를 합친 실제 배포 파일로 전체 사용자 시나리오를 검증하고 공개 여부를 결정한다.

## 완료 기준

- 지정한 소스 버전과 기록된 도구·설정으로 개발자 Windows PC에서 문서화된 절차를 따라 앱·훅 게시와 Inno Setup 설치 파일 생성을 재현할 수 있다.
- 최종 설치 파일에 두 게시 결과의 필요한 실행 파일, 런타임, 의존성과 앱 리소스가 포함되어 있고, 앱·훅·설치 화면과 파일명에 한 곳에서 관리하는 `0.1.0` 버전이 일관되게 반영된다.
- 최종 설치 파일의 이름과 저장 위치가 기록되어 있고 SHA-256 해시와 확인 방법을 제공할 수 있다. 빌드와 패키징 실패가 성공으로 표시되지 않는다.
- 개발 도구와 별도 .NET 런타임이 없는 지원 대상 Windows 11 x64 테스트 환경에서 기존 GIF 없이 설치 후 위젯이 실행된다. 이미지 미등록 상태에서 기본 문구와 빈 이미지 영역이 표시되고, 설정 화면에서 사용자가 이미지를 등록·저장할 수 있다. 설치 동작과 실제 Codex 연동의 완전한 검증은 Spec 2·4와 함께 수행한다.
- CodexPet의 라이선스가 결정·명시되고, 실제 포함된 외부 구성 요소의 라이선스와 필요한 고지를 최종 배포물 또는 함께 제공하는 문서에서 확인할 수 있다. 검토한 구성 요소와 적용한 조건이 기록되어 있다.
- 공개 GitHub Releases에 올릴 설치 파일과 안내 초안이 준비되어 있고, 설치·삭제 방법, 지원 환경, 버전별 변경 사항, 알려진 제한 및 해시 확인 방법을 포함한다. 실제 공개는 Spec 4의 릴리스 판단 이후에 한다.

## 미결정 사항

정확한 Windows 11 버전·에디션, 사용할 .NET SDK와 Inno Setup 버전, 공통 버전 파일의 위치와 빌드 결과 폴더는 실제 환경을 확인하며 정해 기록한다. CodexPet 자체 라이선스와 외부 구성 요소별 고지의 구체적인 형식·위치도 확정해야 한다. Inno Setup의 사용 조건도 확인한다. 설치·훅 등록과 최종 공개는 각각 관련 Spec에서 결정한다.
