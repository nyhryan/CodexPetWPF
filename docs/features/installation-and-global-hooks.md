# Spec 2. 설치·삭제와 전역 훅 연동

## 상태

**구현 및 검증 진행 중.** [배포 준비 대화](../distribution-conversation.md)와 [질문지](installation-and-global-hooks-questions.md)의 답변을 반영했다. 사용자가 실제 설치·Codex 연동·제거의 기본 흐름을 확인했으며, 기존 훅 보존은 격리된 경로에서 시험했다. 상세 결과와 남은 범위는 아래 검증 기록을 참고한다. 최종 배포 환경의 검증과 릴리스 승인은 아직 완료되지 않았다.

## 목적과 범위

사용자가 자신의 Windows 계정에서 CodexPet을 설치하고 훅을 검토·신뢰하면, 다른 로컬 Codex 프로젝트에서도 위젯이 상태 이벤트를 받을 수 있도록 한다. 기존 Codex 설정과 사용자가 만든 이미지·문구를 보호하고, 재설치와 제거 시 CodexPet이 추가한 항목의 처리를 명확히 한다.

- [Spec 1](windows-distribution-package.md)에 따라 Windows 11 x64 로컬 Codex와 Inno Setup 설치 파일을 대상으로 한다. 앱과 훅은 각각 Release·win-x64·self-contained 게시 결과를 사용한다. 정확한 Windows 버전·에디션은 실제 테스트 환경과 함께 정한다.
- 설치한 Windows 사용자 한 명에게만 적용하고, `%LOCALAPPDATA%\CodexPet` 아래에 앱·훅과 사용자 데이터를 구분해 설치한다. 설치 위치는 고정하며 설치 화면에서 변경할 수 없다. 다른 사용자 계정에 설정을 전파하지 않는다. 사용자별 경로와 권한으로 설치하되 관리자 권한 없이 정상 설치되는지는 실제 환경에서 확인한다.
- 클라우드로 조정되는 작업, WSL·원격 컴퓨터, ARM64, 자동 업데이트와 포터블 ZIP은 첫 버전의 지원 범위가 아니다. 로컬 전용 Work의 동작도 환경별 검증 전에는 보장하지 않는다.
- 여러 세션의 상태는 집계하지 않고 도착한 이벤트 순서대로 표시한다. 다른 세션의 이벤트가 표시를 바꿀 수 있다. 위젯을 나중에 실행해도 그 전의 상태를 복원하지 않는다.

## 현재 상태와 의존 관계

- 사용자는 기존 개발용 프로젝트 훅을 `.codex/hooks.json.bak`으로 이름을 바꿔 비활성화했다. 설치 프로그램과 전역 훅 병합·제거 도우미가 추가되었으며, 사용자가 실제 환경에서 설치·Codex 연동·제거의 기본 흐름을 확인했다. 최종 배포 검증은 아직 완료되지 않았다.
- 현재 앱은 `%LOCALAPPDATA%\CodexPet\settings.json`에 문구와 이미지 경로를 저장하고 `%LOCALAPPDATA%\CodexPet\images`에 선택한 이미지 사본을 둔다. 새 진단 로그와 이전 로그의 위치·보관 정책은 [Spec 3 점검 결과](security-review-results.md)를 따른다. 앱·훅 파일과 이 사용자 데이터는 구분해 관리한다.
- Spec 1은 게시·패키징과 배포를, [Spec 3](security-review-and-hardening.md)은 설치 경로와 훅 변경의 보안 검토 및 사용자 데이터 보존 검증을 다룬다. Spec 4는 실제 설치 파일을 이용한 최종 시나리오와 릴리스 판단을 다룬다.

## 설치와 실행 흐름

1. 사용자는 설치 파일을 실행한다. 설치 위치는 고정되어 있으며, 현재 Windows 사용자에게만 적용되는 범위와 필요한 권한을 안내한다.
2. 앱과 훅의 게시 결과를 설치한다. 훅 설정에는 설치 PC에서 결정한 **실제 훅 실행 파일의 절대 경로**를 사용한다. Windows 사용자 이름이나 개발 PC 경로를 배포물에 하드코딩하지 않는다.
3. 해당 사용자의 기본 `~/.codex/hooks.json`에 필요한 이벤트의 훅을 등록한다. 기본 위치가 아닌 Codex 홈이나 프로필은 자동으로 설정하지 않는다. 해당 환경에서는 자동 연동이 보장되지 않음을 밝히고 수동 설정 방법을 제공한다.
4. Windows 로그인 시 자동 시작은 제공하지 않으며 시작프로그램 바로 가기를 만들지 않는다. 설치가 끝나도 위젯을 자동 실행하지 않고, 시작 메뉴 등에서 사용자가 직접 실행하도록 안내한다.
5. 훅 등록까지 성공한 경우에만 설치가 완료되었다고 표시한다. 사용자가 Codex CLI의 `/hooks` 또는 사용 중인 Codex 앱의 훅 화면에서 새로 추가되거나 바뀐 훅을 직접 검토·신뢰하도록 안내한다. 화면 명칭과 실제 동작은 배포 대상 Codex 버전에서 확인한다. 설치 프로그램이 신뢰 확인을 우회하지 않는다.
6. 사용자는 위젯을 직접 실행하고 다른 로컬 프로젝트에서 이벤트 수신을 확인한다. 위젯이 꺼져 있거나 전달에 실패해도 훅은 Codex 작업을 중단하지 않는다.

## 전역 훅 등록과 기존 설정 보존

- [상태 표시 명세](show-state-widget.md)와 Spec 3의 현재 전송 정책에 필요한 `SessionStart`, `SessionEnd`, `Interrupt`, `Stop`, `UserPromptSubmit`, `PreModelRequest`, `PostModelRequest`, `PreToolUse`, `PostToolUse`, `PermissionRequest`를 등록 대상으로 한다. 상태에 영향을 주지 않아 전송하지 않는 이벤트를 추가로 등록할 필요는 없다. 이벤트 지원과 실제 실행은 대상 Codex 버전에서 확인한다.
- 설정 파일이나 `.codex` 폴더가 없으면 다른 설정을 지우지 않고 필요한 파일을 만들 수 있어야 한다. 기존 JSON이 있으면 다른 이벤트, 다른 프로그램의 훅, matcher와 그 밖의 설정을 보존하면서 CodexPet 항목만 추가한다. `config.toml`이나 프로젝트 훅을 덮어쓰지 않는다.
- 사용자 전역 `hooks.json`과 `config.toml`, 프로젝트 설정 및 플러그인의 훅은 함께 실행될 수 있다. 같은 계층에서 두 형식을 함께 사용하면 Codex가 경고할 수 있으므로 이를 안내하고 대상 버전에서 확인한다. 다른 파일의 내용을 변경하거나 기존 항목을 CodexPet 소유로 간주하지 않는다.
- 소유권 판별과 기록 방법은 구현 설계에서 정하고, Codex가 지원하는 설정 형식과 호환되는지 검증한다. 다른 프로그램이나 사용자가 만든 유사한 명령, 사용자가 수정한 항목을 확실한 근거 없이 자동 삭제·교체하지 않는다. 식별이 모호할 때의 안내와 복구 방법을 제공한다.
- 이미 등록된 자기 항목은 재설치·업데이트해도 중복되지 않아야 한다. 고정된 설치 위치의 실제 경로를 사용하고 필요한 경우 자기 항목만 갱신한다. 훅 정의가 바뀌면 Codex에서 다시 검토·신뢰해야 할 수 있음을 안내한다.
- JSON 직렬화와 실제 명령 셸의 인용 규칙을 각각 적용하고, 공백·한글·특수 문자가 있는 경로에서 다른 프로젝트의 현재 작업 디렉터리와 무관하게 올바른 실행 파일이 호출되는지 확인한다. 경로 문자열을 임의로 연결한 예시가 실제 실행 보장을 뜻하지는 않는다.
- 기존 파일이 잘못된 JSON이거나 읽기·쓰기 권한이 없는 경우 원본과 다른 훅을 덮어쓰지 않고 설치 완료로 처리하지 않는다. 문제 파일의 위치와 복구·재시도 방법을 안내한다. 중간 실패 시 이미 복사된 파일이 무조건 사라진다고 가정하지 않으며 남은 파일과 등록 상태를 확인하고 복구 절차를 마련한다.
- 사용자가 이 저장소의 개발용 프로젝트 훅을 직접 `hooks.json.bak`으로 변경해 비활성화했다. 설치 프로그램은 이 파일을 삭제하거나 변경하지 않는다. 다른 프로젝트와 플러그인의 기존 훅도 보존한다.

## 재설치·업데이트·제거

- 재설치와 업데이트는 기존 사용자 문구·이미지와 다른 훅을 보존하고 같은 고정 설치 위치를 사용한다. 위젯이 실행 중이면 이를 알리고 사용자가 직접 종료한 뒤 다시 시도하도록 한다. 설치 프로그램이 자동으로 종료하거나 설치 완료 후 자동으로 실행하지 않는다.
- 제거 시 CodexPet이 관리한다고 확인할 수 있는 전역 훅 항목과 설치 프로그램이 만든 바로 가기를 제거한다. 이 버전은 시작프로그램 바로 가기를 만들지 않는다. 같은 이벤트에 포함된 다른 훅이나 다른 사용자 계정의 설정은 보존한다. 남은 설정이 유효한 JSON인지 확인하며, 빈 파일이나 빈 그룹의 처리도 다른 설정을 보존하도록 설계한다.
- 제거 전에 훅을 정리한다. 설정을 읽거나 쓸 수 없거나 소유 항목을 식별할 수 없어 안전하게 정리할 수 없으면 제거를 멈추고 실행 파일을 삭제하지 않는다. 다른 항목을 강제로 지우지 않으며 문제의 위치와 복구·재시도 방법, 실제로 남은 상태를 안내한다.
- 사용자 설정·이미지 사본, 새 진단 로그 및 이전 진단 로그는 기본적으로 보존한다. 제거 화면에서 **설정·이미지 사본**, **새 로그**, **이전 로그**를 각각 별도로 삭제 선택할 수 있게 하고, 기본값은 모두 보존으로 둔다. 삭제 전에 선택된 대상과 경로를 구분해 안내한다. Spec 3에 따라 **이전 로그는 자동 삭제하지 않으며**, 사용자가 해당 항목을 명시적으로 선택한 경우에만 제거 과정에서 삭제한다. 선택하지 않은 데이터와 원본 이미지, 다른 프로그램의 파일은 건드리지 않는다.

## 오류 안내와 보안

- 설치·훅 등록·제거의 성공 여부를 명확히 표시한다. 권한 부족, 파일 손상, 경로 오류, 중복·소유권 모호성 등으로 전체 흐름을 완료하지 못하면 남은 상태와 재시도 방법을 안내한다.
- [Spec 3 점검 결과](security-review-results.md)의 기존 로그 보존, 최소 이벤트 전송과 사용자 데이터 취급을 따른다. 보안 검토에서 실행 파일 경로·명령 인용, 설정 변경·복구 및 다른 사용자에 대한 영향을 구현 전후로 점검한다. 테스트에는 격리된 계정·설정과 합성 데이터를 사용한다.
- 로그는 기본적으로 오류·실패만 남으며 저장 위치와 이전 로그 삭제 방법을 안내한다. 민감한 원본 이벤트나 설정 문구·이미지 내용을 오류 안내 또는 로그에 넣지 않는다.
- 같은 계정 프로세스의 파이프 위조·선점 가능성은 남아 있으며, 사용자는 이 위험을 0.1.0에서 수용했다. 이 설치 명세의 사용자별 범위나 훅 검토는 파이프 상대방 인증을 보장하지 않는다. 영향과 판단 근거는 [보안 점검 결과](security-review-results.md)를 따른다.

## 검증 기록

### 사용자가 직접 확인한 사항

- 2026-11-10 새 시험용 설치 파일로 설치, 위젯 기본 표시, 이미지·문구 설정, Codex 훅 연동, 설치된 고지 확인과 제거의 여섯 단계를 직접 실행했고 모두 오류 없이 성공했다고 보고했다. 제거 시 **“모든 파일 보존 하지 않기”**를 선택했다고 밝혔다. 선택 대상별로 파일이 실제 삭제되었는지는 에이전트가 별도 확인하지 않았다. 시험 PC는 Windows 11 Enterprise 25H2 x64 빌드 `26200.9711`이며 .NET SDK와 별도 런타임이 설치되어 있었다. 자세한 환경은 [Spec 1 검증 기록](windows-distribution-package.md#2026-11-10-구현-및-검증-기록)을 따른다.
- 2026-11-10 사용자가 직접 시험용 CodexPet 설치 파일을 설치하고, 위젯 실행·Codex 연동·화면과 설정 확인·제거의 네 단계를 수행했으며 문제가 없었다고 보고했다. 실제 환경의 기본 흐름에 대한 사용자 보고다.
- 확인한 Codex 버전, 개별 이벤트, 기존 훅의 존재 여부 및 설치 전후 내용 비교는 구체적으로 보고되지 않았다. 제거 시 선택 대상별 파일 처리 결과도 별도로 확인하지 않았다. 따라서 해당 세부 항목까지 각각 검증한 것으로 간주하지 않는다. 최종 배포 파일에 대한 검증도 아니다.

### 에이전트가 확인한 기존 훅 보존

- 2026-11-10 .NET SDK 10.0.403, Inno Setup 7.1.1을 사용했다. 현재 소스로 설치 보조 프로그램을 다시 게시하고, 기존 앱·훅 게시 결과를 포함해 `TestRoot`를 지정한 격리 시험용 설치 파일을 만들었다. 설치·재설치·제거는 무인 모드로 실행했다.
- 시험용 `hooks.json`에 기존 `Stop`·`PreToolUse` 훅과 matcher, timeout, 별도 `Custom` 이벤트 및 최상위 설정을 넣었다. 각 단계에서 기존 항목의 JSON 내용이 보존되고, CodexPet의 10개 이벤트 훅이 설치 후 각각 한 번만 등록되며 재설치 후에도 중복되지 않고 제거 후 사라진 것을 확인했다.
- 별도로 둔 시험용 `config.toml`과 프로젝트 `hooks.json`의 파일 내용도 세 단계 전후로 동일했다. 시험 경로는 `artifacts/hook-preservation-dfc93aaa5bef4066857b11a2003b22e7/`이며 실제 사용자 훅 설정을 변경하지 않았다.
- 이 시험은 합성 설정의 **내용 보존**을 검사했다. 기존 훅 명령을 실제 Codex에서 실행하지 않았고, 실제 사용자 설정·플러그인 훅이나 다른 Windows 계정을 시험하지 않았다. 시험용 `config.toml`은 보존 여부를 위한 파일로, 인라인 훅 실행은 시험하지 않았다. 설치 화면과 최종 배포 파일도 이 시험의 대상이 아니다.

### 남은 검증

- 실제 기존 `hooks.json`·인라인 `config.toml` 훅·프로젝트 또는 플러그인 훅과 함께 사용할 때 기존 훅의 실행 및 설치·제거 전후 보존을 확인한다. 설정이 없는 경우와 다른 Windows 계정의 영향도 실제 환경에서 구분해 확인한다.
- 위젯 실행 중 재설치·제거, 오류 안내와 복구, 접근 권한 문제, 공백·한글·특수 문자가 포함된 실제 Codex 경로 등을 확인한다. 격리 시험의 경로·실패 사례를 실제 Codex 및 일반 설치 화면 검증으로 간주하지 않는다.
- 사용자 데이터의 보존 및 삭제 선택 각각을 일반 제거 화면에서 확인하고, 개발 도구가 없는 환경과 최종 배포할 동일한 설치 파일로 전체 흐름을 검증한다. 사용자 보고에 구체적인 선택이나 이벤트가 없는 항목은 확인 결과를 보충한다.

## 검증과 완료 기준

다음은 실제 구현과 격리된 Windows 11 x64 환경에서 검증할 항목이다. 최종 설치 파일이 준비되기 전에는 실제 설치 파일에 대한 항목을 완료로 표시하지 않는다.

- [ ] 현재 사용자에게 고정 위치로 설치되며 다른 Windows 계정은 변경되지 않는다. 자동 시작이나 설치 완료 후 자동 실행 없이 사용자가 직접 위젯을 실행할 수 있다. 개발 도구가 없는 환경에서 앱과 훅이 실행된다.
- [ ] 전역 설정이 없는 경우와 기존 `hooks.json`·`config.toml` 및 다른 훅이 있는 경우를 각각 검사해 기존 내용과 동작을 보존한다. 실제 경로에 공백·한글·특수 문자가 있어도 명령이 실행된다.
- [ ] Codex에서 사용자가 훅을 검토·신뢰한 후 다른 로컬 프로젝트의 이벤트를 수신한다. 위젯 미실행 시에도 Codex 작업은 계속된다. 기본 위치가 아닌 Codex 홈의 수동 설정 방법을 안내한다.
- [ ] 재설치·업데이트해도 CodexPet 훅이 중복되지 않고 다른 훅과 사용자 설정·이미지가 보존된다. 위젯 실행 중에는 사용자가 종료 후 재시도하도록 안내하고, 훅 변경 후 신뢰 재검토가 필요한 경우를 안내한다.
- [ ] 잘못된 JSON, 접근 불가 설정, 쓰기 실패, 식별이 불명확한 훅, 설치·제거 도중 실패를 검사한다. 훅 등록 실패 시 설치 완료로 표시하지 않고 훅 정리 실패 시 실행 파일을 삭제하지 않는다. 원본과 다른 훅을 보존하고 실제 남은 상태 및 복구 방법을 정확히 안내한다.
- [ ] 제거 후 CodexPet 소유의 등록·바로 가기만 정리되고 다른 훅은 동작한다. 사용자 문구·이미지 사본, 새 로그와 이전 로그는 기본 보존하며 각 삭제 선택에 따라 처리된다. 이전 로그는 명시적으로 선택할 때만 삭제하고 원본 이미지와 다른 계정의 데이터는 보존한다.
- [ ] Spec 3의 설치 보안 점검을 반영하고, 실제 배포할 설치 파일로 설치 → 신뢰 → 다른 프로젝트에서 사용 → 제거 흐름을 다시 검증해 결과와 미해결 사항을 Spec 4에 전달한다.

## 구현 시 확인할 내용

2026-11-10 항상 위에 표시 기능을 포함한 새 후보의 게시 폴더로 별도 시험용 설치 파일의 격리 설치·재설치·실패 복구·제거 검사를 다시 통과했다. 합성 데이터의 삭제 선택은 모의했으며 실제 후보의 설치·제거 화면이나 실제 기존 훅 실행을 확인한 것은 아니다. [Spec 4 재점검 기록](release-validation-and-distribution.md#2026-11-10-항상-위에-표시-추가-후-재점검)에 파일 식별값과 범위를 기록했다.

같은 날 트레이 기능을 포함한 새 후보의 게시 폴더로 별도 시험용 설치·재설치·실패 복구·삭제 모의 및 제거 검사도 통과했다. [새 후보의 Spec 4 기록](release-validation-and-distribution.md#2026-11-10-트레이-기능-추가-후-재점검)에 결과를 기록했다. 이 시험은 실제 후보 설치 화면이나 기존 훅의 실제 실행을 확인하지 않는다.

앱과 훅은 각각 `%LOCALAPPDATA%\CodexPet\App`, `Hook`에 둔다. 등록한 그룹의 사본은 `Installer\hooks-owned.json`에 기록하고 현재 설정의 그룹과 정확히 일치할 때만 갱신·제거한다. 손상되거나 식별이 불명확한 경우의 복구 방법은 [설치 안내](installation-guide.md)에 기록했다. 실제 Codex 연동의 기본 흐름은 사용자가 확인했으며, 상세 이벤트와 설치 UI의 삭제 선택 및 개발 도구가 없는 별도 Windows 계정에서의 동작은 추가 검증이 필요하다.
