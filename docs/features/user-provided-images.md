# 기본 GIF 제외와 사용자 이미지 등록

## 상태

**답변 반영 — 구현 전 명세.** [질문지](user-provided-images-questions.md)의 답변을 반영했다. 이 문서는 파일 이동이나 프로그램 변경이 이미 이루어졌다는 뜻이 아니다.

## 목적

기존 Tenor GIF를 프로젝트와 배포물에 포함하지 않으면서 사용자가 직접 선택한 이미지와 기본 문구로 Codex 상태를 표시한다. 개발자가 현재 사용하는 GIF는 개인 파일로 남겨, 프로그램 실행 후 설정 화면에서 직접 등록할 수 있다.

## 범위

- 현재 `CodexPet.App/assets`의 GIF 다섯 개를 프로젝트 루트의 `assets` 폴더로 옮겨 로컬에 보존한다. 파일 내용을 삭제하지 않는다.
- 루트 `assets`의 개인 이미지는 Git 추적에서 제외하고, 기존 추적 대상 GIF도 현재 프로젝트의 추적 대상에서 제거한다. 파일은 로컬에 남긴다. `.gitignore`만으로 이미 추적 중인 파일의 추적이 해제되지는 않는다.
- 해당 GIF를 앱의 내장 리소스, 게시 결과 및 설치 파일에 포함하지 않는다. 새로운 복제본을 저장소나 배포물에 추가하지 않는다.
- 앱은 프로젝트 루트 `assets`의 존재나 특정 파일명에 의존하지 않는다. 사용자는 실행 후 설정 화면에서 자신의 이미지 파일을 직접 선택한다. 이 폴더는 개발자의 로컬 보관 장소다.
- 기본 상태 문구는 유지한다. 사용자가 등록해 저장한 이미지와 문구는 같은 Windows 계정에서 재실행·재빌드한 후에도 유지한다.

## 현재 동작과 변경이 필요한 부분

- 현재 구현은 GIF를 프로젝트 리소스에 포함하고 최초 실행과 이미지 오류 시 사용한다. 이 명세를 구현하면 [상태 표시 명세](show-state-widget.md)와 [설정 메뉴 명세](configuration-menu.md)에 반영한 빈 이미지 영역 동작으로 바뀐다.
- 현재 설정 화면은 상태별로 GIF·PNG·JPEG를 등록한다. 저장하면 사용자 이미지 사본을 `%LOCALAPPDATA%\CodexPet\images`에 보관하고 이미지 경로와 문구를 `%LOCALAPPDATA%\CodexPet\settings.json`에 기록한다. 원본 파일을 옮겨도 저장된 사본을 사용할 수 있다.
- 현재 저장된 설정에는 내장 GIF를 가리키는 `asset:idle.gif` 같은 값과 사용자 이미지 경로가 함께 있을 수 있다. 새 버전에서는 제거된 기본 GIF가 없어도 설정을 읽고 사용자 이미지와 문구를 보존해야 한다.
- 현재는 상태마다 이미지와 문구 후보가 하나 이상 있어야 저장할 수 있고 초기화하면 내장 GIF로 돌아간다. 아래에 정한 새 동작에 맞게 변경한다.

## 사용자 흐름

1. 앱을 처음 실행하면 이미지가 없어도 정상 실행하고 현재 상태의 기본 문구를 표시한다. 이미지 영역은 기존 옅은 회색 배경으로 비워 둔다. 설정 화면은 자동으로 열지 않으며, 우클릭 메뉴로 열면 이미지 추가 방법을 안내한다.
2. 사용자는 설정 화면에서 원하는 상태를 고르고 이미지 파일을 추가한다. 이미지 형식, 사본 저장 및 문구 편집은 기존 설정 기능을 따른다.
3. 사용자가 **저장**하면 선택한 이미지 사본과 설정이 유지된다. **취소**하거나 저장하지 않고 닫으면 편집 내용을 적용하지 않는다.
4. 다시 실행하거나 같은 계정에서 재빌드하면 기존 사용자 설정을 불러온다. 다른 계정이나 PC로의 설정 이동은 이번 범위에서 별도로 정하지 않는다.

## 이미지 미등록과 초기화

- 상태별 이미지 후보가 없어도 저장할 수 있다. 일부 상태에만 이미지를 등록해도 저장하며, 이미지가 없는 상태는 문구와 빈 이미지 영역을 표시한다. 문구 후보는 기존처럼 상태마다 하나 이상 있어야 하며 빈 문구는 후보 하나로 인정한다.
- 상태별 또는 전체 초기화 전에 확인한다. 초기화 대상의 이미지 후보는 비우고 문구 후보는 해당 상태의 기본 문구로 되돌린다. 초기화는 저장 전까지 편집 중인 내용이며 취소하면 적용되지 않는다.

## 기존 설정과 이미지 오류

- 기존 설정을 읽을 때 제거된 기본 GIF의 `asset:` 항목만 후보 목록에서 제외하고, 설정 화면에 기본 이미지가 제거되었다고 안내한다. 유효한 사용자 이미지 후보와 사용자 지정 문구는 유지한다. `asset:` 제외 후 후보가 없는 상태는 빈 이미지 영역을 표시한다.
- 설정을 읽는 시점에 설정 파일을 덮어쓸지 다음 저장 시 반영할지는 구현 시 정한다. 사용자 이미지 사본을 삭제하지 않는다.
- 등록된 이미지 중 읽을 수 없는 항목이 있으면 설정 화면에 알린다. 해당 상태에 읽을 수 있는 다른 이미지가 있으면 그 후보를 사용하고, 하나도 없으면 이미지 영역을 비워 둔다. 문구와 다른 정상 설정은 유지한다.

## 다른 명세와의 관계

- [상태 표시 명세](show-state-widget.md), [설정 메뉴 명세](configuration-menu.md), Spec 1의 설치 후 화면 검증에도 이 동작을 반영한다.
- [Spec 1](windows-distribution-package.md)은 게시와 설치 파일에서 기존 GIF가 제외되는지 확인한다. Spec 4는 이미지가 없는 설치본의 실행과 사용자가 이미지를 등록한 뒤 재실행하는 흐름을 검증한다.
- 기존 GIF는 이미 Git에서 추적 중이므로 현재 추적을 중단해도 과거 커밋이나 이미 공개된 복제본에서 자동으로 사라지지 않는다. 공개 전 과거 이력과 배포물의 존재를 확인하되, 이력 변경 여부와 방법은 별도로 결정한다.

## 완료 기준

- 기존 GIF 다섯 개가 로컬 루트 `assets`에 보존되고, 현재 Git 추적 대상과 앱 빌드·게시·설치 파일에는 포함되지 않는다.
- 로컬 `assets`와 기존 GIF가 없는 환경에서도 앱이 실행되고 기본 문구를 표시하며, 상태 전환과 설정 화면을 사용할 수 있다.
- 사용자가 각 상태에 GIF·PNG·JPEG를 추가하고 저장할 수 있으며, 저장된 이미지와 문구는 재실행 및 같은 계정의 재빌드 후에도 유지된다. 저장된 이미지 사본이 있으면 원본 이동 후에도 표시된다.
- 이미지가 없는 상태는 문구와 빈 이미지 영역을 표시하고, 일부 상태에만 이미지를 등록해도 저장할 수 있다. 설정 화면에 이미지 추가 방법이 표시된다.
- 기존 설정에서 `asset:` 항목만 제외하고 제거 안내를 표시하며 유효한 사용자 이미지와 문구는 유지한다. 사용자 이미지 사본을 삭제하지 않는다.
- 읽을 수 없는 이미지를 안내하고 다른 정상 후보를 표시한다. 정상 후보가 없으면 영역을 비운다.
- 초기화 확인 후 대상의 이미지 후보는 비고 문구는 기본값으로 돌아간다. 저장 전 취소하면 초기화가 적용되지 않는다. 이미지가 없는 상태에서도 상태 이벤트 처리와 위젯 종료를 사용할 수 있다.
