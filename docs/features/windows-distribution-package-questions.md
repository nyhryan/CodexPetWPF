# Spec 1. Windows 배포 패키지와 빌드: 결정할 질문

이 문서는 [Spec 1 초안](windows-distribution-package.md)을 완성하기 위한 질문입니다. 원하는 항목의 `[ ]`를 `[x]`로 바꾸거나 `1-A, 2-A, 3-B`처럼 번호와 선택지만 알려주세요. 다른 의견을 직접 적거나 **“추천대로”**라고 답해도 됩니다. 추천은 제안이며 아직 결정된 내용이 아닙니다.

## 1. 어떤 Windows를 지원할까요?

**Windows x64**는 일반적인 인텔·AMD 64비트 PC입니다. ARM64 PC 지원은 별도의 빌드와 실제 환경 확인이 필요할 수 있습니다.

- [x] **A. Windows 11 x64부터 지원합니다.** ARM64는 첫 버전에서 제외합니다. **추천: 첫 테스트 범위를 줄일 수 있습니다.**
- [ ] B. Windows 11 x64와 지원되는 Windows 10 x64 환경도 지원합니다. 각각 검증합니다.
- [ ] C. Windows 11 x64와 ARM64를 지원합니다. 아키텍처별 빌드와 검증이 필요합니다.
- [ ] D. 직접 정하기: ___

정확한 Windows 버전과 에디션은 실제 대상 PC와 .NET 지원 범위를 확인해 확정합니다. [Microsoft의 .NET Windows 지원 표](https://learn.microsoft.com/en-us/dotnet/core/install/windows)를 참고하며, Windows 10은 해당 표에서 지원하는 버전·에디션을 확인해야 합니다. WSL·원격 PC·클라우드 작업은 별도로 결정하지 않는 한 첫 범위에 넣지 않습니다.

## 2. 어떤 형태로 배포할까요?

- [x] **A. 설치 파일 하나를 제공합니다.** 설치 파일 제작에는 Inno Setup을 사용합니다. **추천: 기존 배포 논의와 잘 맞고 친구가 설치하기 쉽습니다.**
- [ ] B. 우선 압축 파일(ZIP)만 제공합니다. 설치와 전역 훅 연결 방법은 별도로 정해야 합니다.
- [ ] C. 설치 파일과 포터블 ZIP을 모두 제공합니다. 두 형태의 동작과 검증이 추가됩니다.
- [ ] D. 다른 설치 도구나 형식: ___

설치 위치, 자동 시작, 기존 훅 설정 병합·삭제는 Spec 2에서 정합니다. [Inno Setup 안내](https://jrsoftware.org/isinfo.php)에 따르면 제작자는 상업적 사용자의 라이선스 구매를 요청합니다. 사용 목적에 맞는 조건은 도구를 채택하기 전에 확인합니다.

## 5. 버전은 어디에서 관리할까요?

앱, 훅, 설치 화면과 파일 이름의 버전이 서로 다르게 표시되지 않도록 하는 선택입니다.

- [x] **A. 프로젝트에서 공통으로 읽는 한 곳에 버전을 두고 빌드에 반영합니다.** 첫 버전은 `0.1.0`입니다. **추천**
- [ ] B. 배포할 때 빌드 명령에 버전을 직접 전달합니다. 첫 버전은 `0.1.0`입니다.

## 답변 후 확정할 내용

- 지원할 Windows 버전·에디션·아키텍처와 실제 검증 환경.
- 설치 파일 제작 도구, 빌드 실행 방법과 도구 버전, 최종 파일명·결과 위치.
- 배포 채널과 접근 범위, 버전의 기준 위치, 함께 제공할 안내와 파일.
- Spec 2의 설치 구현 및 Spec 3의 보안·서명 결정과 연결하는 구체적인 완료 기준.

도구 이름을 위젯에 표시하는 기능은 이 Spec의 결정 사항이 아닙니다. 별도 기능 명세에서 포함 여부를 정하고, 필요할 때 배포물에 반영합니다.
